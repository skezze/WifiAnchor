# WifiBssidTool

Программа для Windows, которая **закрепляет подключение к конкретной точке
доступа или репитеру** в Wi-Fi сети с несколькими точками и одним общим именем
(SSID). Живёт в системном трее.

## Зачем это нужно

Если у сети несколько точек (роутер + репитеры, mesh) с одним SSID, Windows сама
решает, к какой из них подключиться, и часто упорно держится за дальнюю и слабую.
Штатного способа сказать «подключайся именно к этому репитеру» в Windows нет.

WifiBssidTool следит, к какому BSSID (MAC-адресу точки) вы подключены:

- пока вы на выбранной точке, программа **ничего не делает** и не сканирует эфир;
- если Windows увела вас на другую точку, а выбранная доступна, программа
  просит Windows вернуться на неё;
- если выбранная точка недоступна (выключена, вне зоны), программа **продолжает
  сканировать эфир и ищет её**, а как только точка появится, подключается к ней.

## Возможности

- **Значок в трее**: цвет показывает состояние (зелёный: на выбранной точке;
  жёлтый: подключаюсь; красный: выбранная точка недоступна; серый: пауза или
  точка не выбрана). Левый щелчок открывает окно, правый показывает меню:
  открыть окно, сменить точку, пауза, автозапуск, **выход**.
- **Окно настроек**:
  - список точек выбранной сети: название, MAC, сигнал (% и дБм), канал и
    диапазон (2.4 / 5 / 6 ГГц);
  - смена целевой точки в один клик (двойной щелчок или кнопка);
  - ввод MAC вручную, если точку сейчас не видно;
  - **названия точек** («Репитер в спальне»), чтобы не путаться в MAC-адресах;
  - журнал событий.
- **Закрытие окна**: по умолчанию программа остаётся работать в трее. Это
  отключается галочкой в настройках, тогда закрытие окна завершает программу.
- **Автозапуск** вместе с Windows, свёрнутым в трей. Включается в меню значка
  или в настройках.
- **Уведомления**, когда выбранная точка пропала и когда подключение вернулось
  (отключаются).
- Работает через нативный Windows Wi-Fi API (`wlanapi.dll`), без разбора вывода
  `netsh`, поэтому не зависит от языка системы.
- Проверяет результат подключения. Если обычный запрос не сработал, переходит
  к жёсткому переподключению (отключение, затем подключение к нужному BSSID).
- Запускается в одном экземпляре. Повторный запуск просто показывает окно
  уже работающей копии.

## Требования

- Windows 10/11 с Wi-Fi адаптером.
- Для сборки нужен [.NET SDK 10](https://dotnet.microsoft.com/download).
- В Windows должен быть **сохранённый профиль** сети (то есть вы хотя бы раз
  подключались к ней с запоминанием пароля). Программа пароли не хранит и
  профили не создаёт.

## Сборка и запуск

```powershell
dotnet build -c Release
dotnet run -c Release
```

Готовый exe лежит в `bin\Release\net10.0-windows\WifiBssidTool.exe`. Права
администратора не нужны.

Один файл без установленного .NET:

```powershell
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

## Использование

1. Запустите программу. Откроется окно, на вкладке **«Точки»** будет список.
2. Выберите сеть в выпадающем списке (по умолчанию подставляется текущая).
3. Выберите нужный репитер и нажмите **«Закрепить выбранную точку»** или дважды
   щёлкните по строке. Чтобы не путать точки, дайте им названия через
   **«Назвать…»**.
4. Закройте окно. Программа продолжит работать в трее.

Сменить точку можно в любой момент: меню значка → **«Сменить точку…»**. Новая
точка подхватывается сразу, перезапуск не нужен.

Параметры командной строки:

| Параметр | Что делает |
|---|---|
| `--minimized` | запуск без окна, только значок в трее (так запускает автозапуск) |

## Где хранятся данные

Папка `%AppData%\WifiBssidTool\` (открывается кнопкой в настройках):

- `wifi-config.json`: выбранная точка, названия точек, настройки;
- `log.txt`: журнал (при превышении 1 МБ старая часть уходит в `log.txt.old`).

Если рядом с exe лежал `wifi-config.json` от старой консольной версии, он
подхватывается автоматически.

```json
{
  "Ssid": "WLAN-SR",
  "Bssid": "d8:b3:70:d8:19:55",
  "Profile": "",
  "Names": { "d8:b3:70:d8:19:55": "Репитер в спальне" },
  "MinimizeToTrayOnClose": true,
  "ShowNotifications": true
}
```

`Profile` нужен, только если имя профиля Wi-Fi в Windows отличается от SSID.

## Как это работает

1. Раз в секунду читается текущее соединение (`WlanQueryInterface`).
2. Если вы на выбранной точке, больше ничего не делается.
3. Иначе запрашивается скан (`WlanScan`) и читается список точек
   (`WlanGetNetworkBssList`): раз в 15 секунд, если выбранная точка видна, и
   раз в 10 секунд, пока она недоступна.
4. Если выбранная точка видна, вызывается `WlanConnect` с профилем и списком
   разрешённых BSSID из одного адреса.
5. Через 8 секунд проверяется, получилось ли. После двух неудач подряд
   программа сначала делает `WlanDisconnect`, а потом подключается заново.
   Windows гораздо охотнее принимает BSSID, когда соединения нет.

## Ограничения и особенности Windows

- `WlanConnect` — это **запрос**, а не гарантия. Windows может его
  проигнорировать или вернуться на другую точку: у неё свои правила роуминга.
  Программа в этом случае повторяет попытки, но не чаще раза в 10 секунд.
- Если выбранная точка не видна, подключиться к ней невозможно. Программа
  ждёт и ищет её.
- Во время жёсткого переподключения связь кратковременно пропадает.
- Агрессивный роуминг в настройках адаптера (Диспетчер устройств → адаптер →
  Дополнительно → *Roaming Aggressiveness*) лучше поставить на минимум,
  иначе драйвер может сам уводить вас с выбранной точки.
- Точки со скрытым SSID в списке не показываются.
- Поддерживается один адаптер: подключённый, а при его отсутствии первый
  физический.

## Если не подключается

- Проверьте, что профиль сети есть: `netsh wlan show profiles`. Если имя
  отличается от SSID, укажите его в `wifi-config.json` в поле `Profile`.
- В окне на вкладке «Точки» выбранная точка должна быть в списке с приемлемым
  сигналом. Пометка «не видна» значит, что в эфире её нет.
- Закройте другие программы, которые управляют Wi-Fi (фирменные утилиты
  производителя адаптера и т.п.).
- Смотрите вкладку «Журнал»: коды ошибок Windows выводятся с текстом.
